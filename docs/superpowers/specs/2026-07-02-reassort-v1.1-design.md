# `tessera reassort` v1.1: coverage-aware call + parent constellation -- design

## Context

The v1 `reassort` command (merged, PR #17) types each query segment against its own Nextclade
dataset and calls reassortment by nearest-reference-strain consistency. An audit of v1 found the
call model is only sound for the two-segment probe it was validated on, and that the command drops
part of the spec's intended output. This spec addresses the substantive findings; the trivial ones
(clade label of an example-sequence tip; transient-vs-genuine network failure) are left as noted
limitations.

Findings addressed here, by audit number:

- **#1** The clonal call (`set.intersection` over every segment's top-k nearest strains) treats a
  parent strain that is *not cross-typed in a given segment's tree* as evidence of reassortment,
  when it is really absence of information. Because cross-typing coverage between segment datasets
  is limited (~25% of strains overlap between the H3N2 HA and NA trees), that miscount compounds
  with segment count: a genuinely clonal whole-genome flu isolate (8 segments) essentially never has
  one strain in the top-k of all eight independent trees, so the verdict degrades to "always
  reassortant". v1 was never exercised past two segments.
- **#2** The design (`2026-07-02-reassort-command-design.md`, Architecture) calls for grouping
  segments by donor strain/lineage. v1 emits only a binary verdict plus each segment's single
  nearest strain, so a partial reassortant (the common 7+1 single-gene swap) is not characterised.
- **#3** The verdict is monotonic in `TOP_K` (larger -> always clonal, smaller -> always
  reassortant) with no principled selection, and `TOP_K` is a hard-coded constant that the v1 docs
  nonetheless describe as tunable. There is no user knob.
- **#4** `skani_query_ani` returns `(ANI, query_alignment_fraction)`, but the rank uses ANI only.
  A tip that aligns over a small fraction of the segment at high ANI outranks a true full-length
  match, so the reported nearest strain can be wrong.
- **#5** The per-segment `try/except` wraps only `resolve_dataset`; `build_pool` and
  `skani_query_ani` are outside it, so one segment too short for skani, or one transient pool-build
  failure, aborts the whole run -- asymmetric with the design's stated non-fatal-per-segment intent.
- **#8** Only the pure `_call_reassortment` and CLI parameter introspection are unit-tested;
  `assign_segments` orchestration is exercised only by the opt-in two-segment harness, so the #1
  degradation would never be caught by CI.

Out of scope (unchanged from v1): no intragenic per-segment recombination scan; no change to the
single-backbone `detect`/`recomb` path; no new runtime dependency.

## The call model (#1, #2, #3)

The v1 error is a single-set intersection that cannot distinguish "different parent" from "cannot
tell". v1.1 makes every judgment **pairwise** and uses an ANI **margin** instead of a rank cutoff.

For each assigned segment `i`, let `best_i` be its highest ANI to any reference tip, and

```
cand_i = { strain : ani_i(strain) >= best_i - margin }        # the near-best parent set
universe_i = { every strain typed in segment i's dataset }    # the tips build_pool returned
```

For an unordered segment pair `(i, j)` the relation is exactly one of:

- **concordant** -- `cand_i & cand_j != {}`: at least one strain is near-best for both segments, so
  one parent explains both. The shared strains are the pair's candidate parent.
- **discordant** -- not concordant, and `(cand_i & universe_j) != {}` or `(cand_j & universe_i)
  != {}`: a near-best parent of one segment is *typed in the other segment's tree* yet is not
  near-best there. The segments are cross-typed against a common strain vocabulary and genuinely
  prefer different parents -- positive evidence of reassortment.
- **uninformative** -- neither segment's near-best parents appear in the other's tree. Cross-typing
  is too sparse to compare; no call. (This is the case v1 silently scored as reassortment.)

**Constellation (#2).** Build a graph over the assigned segments with an edge for every concordant
pair. Connected components are the **parent groups**; each group reports its member segments and the
intersection of its members' `cand` sets (the strain(s) that explain the group). A 7+1 reassortant
yields two components rather than a bare "reassortant".

**Verdict.**

- `reassortant` -- at least one pair is discordant.
- `clonal` -- no pair is discordant, and the concordant edges link *all* assigned segments into a
  single component (one parent explains every segment).
- `undetermined` -- otherwise: fewer than two assigned segments, no informative pairs, or partial
  linkage (concordant edges exist but do not connect all segments, with no discordant pair). This
  is the honest "no reassortment evidence, but cross-typing is too incomplete to confirm clonality"
  case; the per-pair notes record why.

This fixes #1 directly: for a clonal whole-genome isolate with sparse cross-typing, most pairs are
uninformative and the informative ones are concordant, so the verdict is `clonal` or `undetermined`
-- never `reassortant` -- because missing coverage no longer counts as disagreement.

The verdict vocabulary (`reassortant` / `clonal` / `undetermined`) is unchanged, so the harness
frontier scorer (`_score_frontier_reassortant`) needs no change.

Approaches considered and rejected: (B) keep the binary intersection but restrict it to
cross-typed strains -- still cannot separate uninformative from discordant, so #1 persists as
segment count grows; (C) a distance-distribution / null-model test per segment -- more machinery
than a v1.1 warrants.

## Architecture

**New pure module `src/tessera/reassort/constellation.py`** -- the methodology, no I/O:

```
@dataclass
class ParentGroup:
    segments: list[str]          # segment names in this component
    parent_strains: list[str]    # strains that explain the group (cand intersection; may be empty)

@dataclass
class Constellation:
    groups: list[ParentGroup]
    verdict: str                 # "reassortant" | "clonal" | "undetermined"
    pair_notes: list[str]        # one line per informative/uninformative pair, for faithful output

def call_constellation(
    candidates: dict[str, list[tuple[str, float]]],   # segment -> [(strain, ani)], best first
    universes: dict[str, set[str]],                   # segment -> all strains in its dataset
    margin: float,                                    # ANI window for the near-best set
) -> Constellation
```

`candidates` holds only the assigned segments. `cand_i` is derived inside the function from
`candidates[i]` and `margin` (`ani >= candidates[i][0].ani - margin`). Grouping is a small
union-find / connected-components pass over concordant edges. The function is deterministic and
fully unit-testable.

**`src/tessera/reassort/assign.py`** keeps the per-segment I/O and now, per assigned segment,
collects the near-best candidate list and the strain universe, then delegates the verdict:

- Rank tips by `(ANI, AF)` and drop any tip below `MIN_AF` (`#4`): the ranked set is
  `[t for t in tips if ani[t][0] >= ani_floor and ani[t][1] >= MIN_AF]`, sorted by ANI descending.
- `candidates[seg] = [(strip_sequence_extension(t.name), ani[t][0]) for t in ranked]` (capped at an
  internal `TOP_K` safety bound so a pathological tree cannot blow up the pair sets).
- `universes[seg] = {strip_sequence_extension(t.name) for t in tips}`.
- `_call_reassortment` is removed; `assign_segments` calls `call_constellation(...)` and stores the
  result on `ReassortmentResult`.

`ReassortmentResult` keeps `segments` and `verdict` (unchanged consumers: the CLI and the harness),
and gains `groups: list[ParentGroup]` and `pair_notes: list[str]`.

**Error handling (#5).** The per-segment `try/except` widens to cover `resolve_dataset`,
`build_pool`, and `skani_query_ani`. Any per-segment failure records that segment `unassigned`
(with the exception logged) and continues. `skani_available()` is still checked once up front and
raises `UserInputError` if skani is missing.

## CLI (#3, #6)

`cmd_reassort.py` gains `--margin FLOAT` (default `DEFAULT_MARGIN = 0.5`, in ANI percentage points),
passed through to `assign_segments`. The hard-coded `TOP_K` is no longer described as tunable; it is
an internal cap. The `--dataset SEGMENT=path`, `--ani-floor`, `--email`, `-q/-o` options are
unchanged.

Output:

- `reassortment.tsv` -- unchanged per-segment columns plus a `parent_group` column (the index of
  the segment's component, or empty for unassigned).
- A `constellation.tsv` -- one row per parent group: `group_index`, `segments` (comma-joined),
  `parent_strains` (comma-joined).
- The text mosaic becomes group-oriented, e.g.
  `group 1 {HA,PB2,PB1,NP,MP,NS} = A/X | group 2 {NA,PA} = A/Y -> reassortant`, followed by the
  verdict and, when the verdict is `undetermined`, the coverage reason from `pair_notes`.

Docs: `docs/reference-panels.md` notes that flu auto-typing needs the `nextclade` CLI or explicit
`--dataset` overrides (there is no influenza taxon alias, so without `nextclade` every flu segment
resolves to nothing and is left unassigned), and documents `--margin` and the constellation output.

## Data flow

```
multi-FASTA query
  -> per segment (each in its own try/except):
       resolve dataset -> build_pool tips -> skani ANI+AF
       -> rank by (ANI, AF), drop below ani_floor / MIN_AF
       -> candidates[seg] = near-best [(strain, ani)]; universe[seg] = all tip strains
  -> call_constellation(candidates, universes, margin)
       -> pairwise concordant / discordant / uninformative
       -> connected components = parent groups; verdict from discordance + linkage
  -> reassortment.tsv + constellation.tsv + text mosaic
```

## Testing / verification

CI unit tests (no binaries):

- `call_constellation`:
  - two concordant segments -> `clonal`, one group.
  - one discordant pair -> `reassortant`, two groups.
  - **eight-segment clonal isolate with sparse cross-typing** (each segment's near-best strain
    typed in only a few other trees) -> `clonal` or `undetermined`, never `reassortant` -- the
    regression that pins #1.
  - 7+1: seven segments share strain A, one segment discordant on strain B -> `reassortant`, the
    seven in one group and the odd one out in its own.
  - partial linkage (concordant but not fully connected, no discordant pair) -> `undetermined` with
    a coverage note.
  - fewer than two assigned segments -> `undetermined`.
- `assign_segments` (stubbed, #8): monkeypatch `resolve_dataset`, `build_pool`, `skani_query_ani`
  to assert the AF floor drops low-AF tips, the `candidates`/`universes` handed to
  `call_constellation` are correct, an unresolved dataset -> `unassigned`, and a `build_pool` /
  `skani_query_ani` exception -> `unassigned` (non-fatal), not an aborted run.
- CLI: `--margin` is accepted and forwarded (parameter introspection, as in v1).

Opt-in end-to-end (aligner env, not CI): `python validation/run_hybrids.py --frontier reassort_flu`
still XPASSes (verdict `reassortant`, now with a two-group constellation). Record the constellation
output in `validation/attribution-results.md`.

`ruff check src tests validation` clean; CI coverage floor (80%) holds.

## Edge cases

- **Single assigned segment** -> `undetermined` (needs >= 2).
- **All pairs uninformative** (disjoint strain vocabularies) -> `undetermined`, with a note that the
  segment datasets share too few strains to compare.
- **Duplicate segment record names** -- out of scope for this spec (noted v1 limitation #7); the
  first-token name still keys the temp file and the candidate dict.
- **`margin` too wide** -> everything concordant -> `clonal`; **too narrow** -> more uninformative
  pairs -> `undetermined`. The default 0.5 ANI points is a starting value; the harness gate may
  retune it for validity, not to force a result.

## Scope / non-goals

- v1.1 = coverage-aware pairwise call + parent constellation + the #4/#5/#8 robustness fixes and the
  `--margin` knob. No intragenic per-segment scan; no `detect`/`recomb` change; no new runtime
  dependency.
- Audit items left as documented limitations: example-sequence clade label (#9), transient-network
  vs genuine-unassigned (#10), duplicate segment names (#7), sequential per-segment fetching.
